บทเรียนที่ 8 · โปรเจกต์ตัวอย่าง

ประกอบร่างเป็นระบบแจ้งเหตุความปลอดภัยฉบับสมบูรณ์

ใช้เวลาทำประมาณ 30 นาที · จุดรวมทุกบทที่ผ่านมาเป็นแอปเดียว

เป้าหมาย · สร้างระบบเงินเดือน/ความปลอดภัยใช้เองที่ ESS

เดินทางมาไกลมากจากบทที่ 1 ตอนนี้มีฟอร์มที่รับข้อมูล, เซิร์ฟเวอร์ที่ประมวลผล, และฐานข้อมูลที่เก็บถาวรครบแล้ว สิ่งเดียวที่ยังขาดคือ หน้าดูรายการทั้งหมด — เพราะตอนนี้พอส่งฟอร์มไปแล้ว ไม่มีใครเห็นภาพรวมว่ามีรายงานอะไรบ้าง วันนี้จะเติมส่วนสุดท้ายนี้ให้ครบ

1. สร้างหน้า reports-list.html

สร้างไฟล์ใหม่ในโฟลเดอร์ public ข้างๆ report.html:

<!DOCTYPE html>
<html lang="th">
<head>
  <meta charset="UTF-8">
  <title>รายการที่แจ้งไว้ทั้งหมด</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <h1>รายการแจ้งเหตุทั้งหมด</h1>
  <table id="reports-table">
    <thead>
      <tr><th>วันที่</th><th>ผู้แจ้ง</th><th>สถานที่</th><th>ความรุนแรง</th></tr>
    </thead>
    <tbody><!-- JS จะเติมแถวตรงนี้ --></tbody>
  </table>
  <a href="report.html">+ แจ้งเหตุใหม่</a>

  <script src="reports-list.js"></script>
</body>
</html>

2. ดึงข้อมูลมาแสดงด้วย JavaScript

สร้าง reports-list.js:

window.addEventListener('DOMContentLoaded', async () => {
  const response = await fetch('/api/reports');
  const reports = await response.json();

  const tbody = document.querySelector('#reports-table tbody');

  reports.forEach((r) => {
    const row = document.createElement('tr');
    row.innerHTML = `
      <td>${r.incidentDate}</td>
      <td>${r.reporterName}</td>
      <td>${r.location}</td>
      <td>${r.severity}</td>
    `;
    tbody.appendChild(row);
  });
});

DOMContentLoaded คือ event ที่บอกว่า "หน้าโหลด HTML เสร็จแล้ว" — ต้องรอ event นี้ก่อน เพราะถ้ายังไม่โหลดเสร็จ document.querySelector('#reports-table') จะยังหา element ไม่เจอ ส่วน forEach ก็เหมือนการวน loop ผ่าน array ปกติที่คุ้นเคยจาก MQL5

3. ผลลัพธ์ที่ควรได้

ตัวอย่างข้อมูลจำลอง (ของจริงจะดึงจากฐานข้อมูลที่คุณกรอกไว้เอง):

วันที่ผู้แจ้งสถานที่ความรุนแรง

2026-08-28วิภา ทองคำโกดังสินค้า Bต่ำ
2026-08-25ประยุทธ สายชลลานจอดรถสูง

ตัวอย่างที่ 2 — ข้อมูลจำลอง 3 แถว (ของคุณจริงจะมาจาก reports.db)

4. โครงสร้างไฟล์ทั้งโปรเจกต์ตอนนี้

ess-safety-app/
├── server.js          ← Express + SQLite (บทที่ 5-7)
├── reports.db          ← ฐานข้อมูล (สร้างอัตโนมัติตอนรันครั้งแรก)
├── package.json
└── public/
    ├── report.html      ← ฟอร์มแจ้งเหตุ (บทที่ 2-3)
    ├── style.css         ← สไตล์ที่ใช้ร่วมกันทุกหน้า (บทที่ 3)
    ├── app.js            ← จัดการฟอร์ม + fetch POST (บทที่ 4, 6)
    ├── reports-list.html ← หน้ารายการทั้งหมด (บทนี้)
    └── reports-list.js   ← ดึงข้อมูล + render ตาราง (บทนี้)

นี่คือโครงสร้างเว็บแอประดับ internal tool ทั่วไปจริงๆ — ไม่ซับซ้อนไปกว่านี้มากนักแม้แต่ในระบบที่ใช้งานจริงในบริษัท ต่างกันแค่เรื่องขนาดข้อมูลกับจำนวนฟีเจอร์

ต่อยอดได้อีกถ้าอยากลองเอง

ลองเพิ่มปุ่ม "ลบรายการ" (route DELETE /api/reports/:id) หรือช่องค้นหา/กรองตามความรุนแรง ดูก็ได้ ถ้าไม่รู้จะเริ่มตรงไหนถามได้เลย เป็นวิธีฝึกที่ดีมากเพราะทุกอย่างที่ต้องใช้เรียนมาหมดแล้วในคอร์สนี้

ทบทวนทั้งเส้นทาง (ครอบคลุมทุกบท)

1. ส่วนไหนของเว็บแอปที่ทำหน้าที่ "เก็บข้อมูลถาวร"?

2. คำสั่งไหนที่หยุดไม่ให้เบราว์เซอร์รีโหลดหน้าตอน submit ฟอร์ม?

3. HTTP method แบบไหนที่ควรใช้ตอน "ขอดูรายการรายงานทั้งหมด" (ไม่เปลี่ยนแปลงข้อมูลอะไร)?

4. เหตุผลหลักที่เปลี่ยนจากเก็บใน array มาเป็น SQLite คืออะไร?

บทต่อไปจะเรียนอะไร
