บทเรียนที่ 4 · ทำให้หน้าเว็บโต้ตอบได้

JavaScript ฝั่งเบราว์เซอร์: ดักจับการกดปุ่ม

ใช้เวลาทำประมาณ 20-25 นาที · ต่อยอดจาก report.html + style.css ในบทที่แล้ว

เป้าหมาย · สร้างระบบเงินเดือน/ความปลอดภัยใช้เองที่ ESS

ฟอร์มตอนนี้หน้าตาดีแล้ว แต่กดปุ่ม "ส่งรายงาน" ยังไม่มีอะไรเกิดขึ้นเลย เพราะเบราว์เซอร์ไม่รู้ว่าต้องทำอะไร — นี่คือหน้าที่ของ JavaScript ภาษาเดียวที่รันในเบราว์เซอร์ได้โดยตรง เพราะคุณมีพื้นฐาน MQL5 มาก่อน ตรรกะพื้นฐาน (ตัวแปร, if, loop) จะคุ้นเคยเร็ว — บทนี้เน้นเฉพาะส่วนที่เป็น "ของเว็บโดยเฉพาะ"

1. เชื่อม JavaScript เข้ากับ HTML

สร้างไฟล์ app.js ข้างๆ report.html แล้วเชื่อมด้วย <script> ก่อนปิด </body>:

<body>
  ... ฟอร์มทั้งหมด ...

  <script src="app.js"></script>
</body>

วางไว้ท้าย <body> เพราะตอนสคริปต์รัน ต้องมีฟอร์มโหลดเสร็จอยู่ในหน้าแล้ว ถ้าวางไว้บนสุดตั้งแต่ <head> สคริปต์จะรันก่อนฟอร์มโหลดเสร็จ แล้วหาฟอร์มไม่เจอ

2. DOM: วิธีที่ JavaScript "มองเห็น" หน้าเว็บ

เบราว์เซอร์แปลง HTML เป็นโครงสร้างต้นไม้ในหน่วยความจำ เรียกว่า DOM (Document Object Model) — JavaScript ใช้ document.querySelector() เพื่อ "หยิบ" element ที่ต้องการมาใช้งาน: 

const form = document.querySelector('form');
const nameInput = document.querySelector('#reporter-name');

console.log(nameInput.value); // ค่าที่คนกรอกไว้ตอนนี้

เทียบกับ MQL5: document.querySelector คล้ายการ ObjectFind หา object บนกราฟ — ต่างกันตรงที่นี่หาจาก HTML element แทน

3. ดักจับ event ตอนกด submit

form.addEventListener('submit', function (event) {
  event.preventDefault(); // หยุดพฤติกรรมเริ่มต้น (รีโหลดหน้า)
  console.log('กดส่งฟอร์มแล้ว!');
});

ปกติเมื่อกด submit เบราว์เซอร์จะรีโหลดหน้าใหม่ทันที — เป็นพฤติกรรมเก่าแก่ตั้งแต่ยุคเว็บแรกๆ event.preventDefault() คือคำสั่งบอกว่า "หยุดก่อน อย่าเพิ่งรีโหลด ให้ JavaScript จัดการเอง" ซึ่งจำเป็นมาก เพราะบทหน้าเราจะส่งข้อมูลผ่าน JavaScript แทน (ไม่ให้หน้ารีโหลดทิ้งข้อมูลไปก่อน)

4. อ่านค่าจากทุกฟิลด์พร้อมกันด้วย FormData

แทนที่จะอ่านทีละช่อง ใช้ FormData เก็บค่าทั้งฟอร์มเป็นก้อนเดียว:

form.addEventListener('submit', function (event) {
  event.preventDefault();

  const data = new FormData(form);
  const report = {
    reporterName: data.get('reporterName'),
    incidentDate: data.get('incidentDate'),
    location: data.get('location'),
    incidentType: data.get('incidentType'),
    severity: data.get('severity'),
    details: data.get('details'),
  };

  console.log(report);
});

data.get('reporterName') จะดึงค่าจาก input ที่มี name="reporterName" — นี่คือเหตุผลที่บทที่ 2 ให้ทุก input ใส่ name ไว้ ไม่ใช่แค่ id

5. ตรวจสอบข้อมูลก่อนส่ง (Client-side validation)

เพิ่มการเช็คง่ายๆ ก่อนถือว่าข้อมูล "พร้อมส่ง" เช่น บังคับให้เลือกระดับความรุนแรงก่อน: 

if (!report.severity) {
  alert('กรุณาเลือกระดับความรุนแรงก่อนส่ง');
  return; // ออกจากฟังก์ชัน ไม่ทำอะไรต่อ
}

console.log('ข้อมูลครบถ้วน พร้อมส่ง:', report);

ข้อสำคัญ: การเช็คแบบนี้เช็คแค่ ฝั่งเบราว์เซอร์ เพื่อความสะดวกของผู้ใช้เท่านั้น ยังต้องเช็คซ้ำที่ฝั่ง backend ด้วยเสมอ (บทที่ 5) เพราะคนที่ไม่หวังดีสามารถส่งข้อมูลตรงมาที่ server โดยข้ามเบราว์เซอร์ไปเลยก็ได้

แผนภาพ 3 — ลำดับเหตุการณ์ตั้งแต่กดปุ่มจนข้อมูลพร้อมส่ง

ทดสอบด้วย console

เปิด Developer Tools ในเบราว์เซอร์ (กด F12 หรือคลิกขวา → Inspect) ไปแท็บ Console แล้วลองกรอกฟอร์มกด submit ดู ควรเห็นข้อมูลที่กรอกไว้โผล่ใน console เป็น object — ถ้าไม่เห็นอะไรเลย ให้เช็คว่าไฟล์ app.js เชื่อมถูกต้องหรือมี error สีแดงขึ้นไหม ถามได้เลยถ้าติด
