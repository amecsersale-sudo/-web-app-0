เชื่อม Frontend เข้ากับ Backend ด้วย fetch

ใช้เวลาทำประมาณ 25 นาที · ใช้ไฟล์จากบทที่ 2-4 (ฟอร์ม) และบทที่ 5 (server.js)

เป้าหมาย · สร้างระบบเงินเดือน/ความปลอดภัยใช้เองที่ ESS

ตอนนี้มีทั้งฟอร์ม (frontend) และเซิร์ฟเวอร์ (backend) แยกกันอยู่คนละไฟล์ — วันนี้จะต่อสองอย่างนี้เข้าด้วยกันจริงๆ เป็นครั้งแรกที่กด "ส่งรายงาน" แล้วข้อมูลวิ่งข้ามจากเบราว์เซอร์ไปถึงเซิร์ฟเวอร์จริง

1. ให้ Express เสิร์ฟไฟล์ HTML ของเราเอง

ก่อนอื่น ย้าย report.html, style.css, app.js เข้าไปในโฟลเดอร์ชื่อ public ข้างๆ server.js แล้วเพิ่มบรรทัดนี้ใน server.js: 

app.use(express.static('public'));

บรรทัดนี้บอก Express ว่า "ถ้ามีคนขอไฟล์ไหนที่อยู่ในโฟลเดอร์ public ให้ส่งไฟล์นั้นไปเลย" ตอนนี้เปิด http://localhost:3000/report.html จะเห็นฟอร์มของเราที่เสิร์ฟจาก server เดียวกัน — สำคัญเพราะทำให้ไฟล์ HTML กับ API อยู่ที่ "บ้าน" เดียวกัน (origin เดียวกัน) เลยไม่มีปัญหาเรื่อง CORS ให้ปวดหัว

2. แก้ app.js ให้ยิง fetch จริง แทน console.log

จากบทที่ 4 เรามี object report พร้อมส่งอยู่แล้ว แค่เปลี่ยนตรงส่วนท้าย:

form.addEventListener('submit', async function (event) {
  event.preventDefault();

  const data = new FormData(form);
  const report = {
    reporterName: data.get('reporterName'),
    incidentDate: data.get('incidentDate'),
    location: data.get('location'),
    incidentType: data.get('incidentType'),
    severity: data.get('severity'),
    details: data.get('details'),
  };

  if (!report.severity) {
    alert('กรุณาเลือกระดับความรุนแรงก่อนส่ง');
    return;
  }

  const response = await fetch('/api/reports', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(report),
  });

  const result = await response.json();
  alert(result.message);
  form.reset();
});

3. async/await คืออะไร (ทำไมต้องมี)

การส่งข้อมูลผ่านเครือข่ายไม่เกิดขึ้นทันที (ต้องรอเดินทางไปเซิร์ฟเวอร์แล้วรอตอบกลับ) — fetch() จึงคืนค่าเป็น "สัญญา" (Promise) ว่าจะได้คำตอบในอนาคต ไม่ใช่ทันที

await คือคำสั่งบอกว่า "รอผลลัพธ์ตรงนี้ก่อน ค่อยไปบรรทัดถัดไป" ส่วน async หน้าฟังก์ชันคือการอนุญาตให้ฟังก์ชันนั้นใช้ await ข้างในได้ — เทียบง่ายๆ เหมือนสั่งอาหารเดลิเวอรี่ แล้วรอจนของมาส่งถึง ก่อนจะกินได้ (ไม่ใช่ตัดจบไปกินอย่างอื่นก่อนของมาถึง)

4. แก้ server.js ให้เก็บรายงานไว้ใน array

ตอนนี้ backend แค่ log ข้อมูลอย่างเดียว บทนี้ให้เก็บไว้ในหน่วยความจำก่อน (ยังไม่ถาวร — บทหน้าจะทำให้ถาวรด้วย database):

const reports = []; // เก็บชั่วคราวในหน่วยความจำ

app.post('/api/reports', (req, res) => {
  const report = { id: reports.length + 1, ...req.body, createdAt: new Date() };
  reports.push(report);
  res.json({ success: true, message: 'บันทึกรายงานแล้ว (รายการที่ ' + report.id + ')' });
});

app.get('/api/reports', (req, res) => {
  res.json(reports);
});

...req.body คือการ "แกะ" ทุกฟิลด์ใน object ที่ส่งมาออกมาใส่ใน object ใหม่ (คล้ายการ copy ทุกช่องของ struct ใน MQL5 มาใส่อีกตัวหนึ่ง)

5. ทดสอบวงจรเต็ม

  1. รัน node server.js
  2. เปิด http://localhost:3000/report.html
  3. กรอกฟอร์มให้ครบ กด "ส่งรายงาน"
  4. ควรเห็น alert แจ้งว่าบันทึกสำเร็จ พร้อมเลขรายการ
  5. เปิด http://localhost:3000/api/reports ในแท็บใหม่ — ควรเห็นข้อมูลที่เพิ่งส่งเป็น JSON

ถ้าทำสำเร็จ นี่คือเว็บแอปที่ครบ 3 ส่วนแรกตามที่เรียนมาตั้งแต่บทที่ 1 แล้ว — frontend, backend, และ "ที่เก็บข้อมูล" (แม้จะยังไม่ถาวรก็ตาม)

ถ้าปิด/เปิด server ใหม่แล้วข้อมูลหาย

ถูกต้องแล้ว! เพราะตอนนี้เก็บไว้ใน array ในหน่วยความจำ พอ restart server หน่วยความจำถูกล้าง ข้อมูลก็หายไปด้วย นี่คือปัญหาที่บทเรียนที่ 7 (ฐานข้อมูล) จะแก้ให้ ถ้าอยากรู้ว่าทำไมไม่เก็บลงไฟล์ตรงๆ เลย ถามได้เลย
