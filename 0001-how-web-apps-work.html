บทเรียนที่ 1 · ภาพรวมก่อนลงมือ

Web App ทำงานอย่างไร?

ใช้เวลาอ่านประมาณ 8-10 นาที · ไม่ต้องเขียนโค้ดในบทนี้ แค่ทำความเข้าใจภาพรวมก่อน

เป้าหมาย · สร้างระบบเงินเดือน/ความปลอดภัยใช้เองที่ ESS

ก่อนจะลงมือเขียนโค้ดบรรทัดแรก เราต้องเห็นภาพรวมก่อนว่า เวลาคนในบริษัทเปิดเว็บขึ้นมา "แจ้งเหตุความปลอดภัย" หรือ "เช็กสลิปเงินเดือน" เบื้องหลังมันเกิดอะไรขึ้นบ้าง — ใครทำหน้าที่อะไร ข้อมูลเดินทางไปไหน และเก็บอยู่ที่ไหนตอนปิดเบราว์เซอร์ไปแล้ว

เว็บแอปทุกตัว ไม่ว่าจะเล็กหรือใหญ่แค่ไหน ประกอบด้วย 3 ส่วนหลัก ที่ทำงานคนละหน้าที่กัน:

1. Frontend — สิ่งที่คนกดเห็นในเบราว์เซอร์

คือหน้าตาเว็บที่พนักงานเห็นและโต้ตอบด้วย เช่น ฟอร์มแจ้งเหตุ ปุ่ม "ส่งข้อมูล" ตารางแสดงรายชื่อพนักงาน — เขียนด้วย HTML (โครงสร้าง), CSS (หน้าตา/สี/จัดวาง) และ JavaScript (การโต้ตอบ เช่น กดปุ่มแล้วเกิดอะไรขึ้น) โค้ดส่วนนี้ทำงาน บนเครื่องของผู้ใช้ ไม่ใช่บนเซิร์ฟเวอร์บริษัท

2. Backend — ตัวประมวลผลที่อยู่บนเซิร์ฟเวอร์

คือโปรแกรมที่รันอยู่บนเครื่องเซิร์ฟเวอร์ (ไม่ใช่เครื่องพนักงาน) ทำหน้าที่รับคำขอจาก frontend เช่น "บันทึกรายงานอุบัติเหตุนี้หน่อย" ตรวจสอบสิทธิ์ว่าใครมีสิทธิ์ดูข้อมูลเงินเดือนใคร คำนวณ แล้วส่งผลลัพธ์กลับไป — ในหลักสูตรนี้เราจะใช้ Node.js เขียน backend เพราะใช้ภาษา JavaScript ตัวเดียวกับ frontend ได้เลย ไม่ต้องเรียนสองภาษา

3. Database — ที่เก็บข้อมูลถาวร

เมื่อพนักงานปิดเบราว์เซอร์ไป ข้อมูลที่กรอกไว้ต้อง ไม่หายไปด้วย — นี่คือหน้าที่ของฐานข้อมูล ที่เก็บข้อมูลไว้ถาวรบนเซิร์ฟเวอร์ เช่น รายชื่อพนักงานทุกคน ประวัติการแจ้งเหตุทั้งหมดย้อนหลัง — เฉพาะ backend เท่านั้นที่คุยกับฐานข้อมูลได้โดยตรง frontend จะต้องขอผ่าน backend เสมอ (เพื่อความปลอดภัยของข้อมูล)

แผนภาพ 1 — เส้นทางคำขอ/คำตอบระหว่างสามส่วนของเว็บแอป

HTTP: ภาษากลางที่ frontend คุยกับ backend

ทุกครั้งที่เบราว์เซอร์อยากได้อะไรจากเซิร์ฟเวอร์ มันจะส่ง HTTP request (คำขอ) ไปตาม URL ที่กำหนด แล้วเซิร์ฟเวอร์จะตอบกลับมาเป็น HTTP response (คำตอบ) — เหมือนส่งจดหมายไปถามแล้วรอคำตอบกลับมา คำขอที่ใช้บ่อยมี 2 แบบหลักๆ:

  • GET — "ขอดูข้อมูลหน่อย" เช่น ขอดูรายชื่อพนักงานทั้งหมด (ไม่เปลี่ยนแปลงข้อมูลอะไร)
  • POST — "ขอส่งข้อมูลใหม่เข้าไป" เช่น ส่งฟอร์มแจ้งเหตุความปลอดภัยที่กรอกเสร็จแล้ว

ตัวอย่างจริง: พนักงานแจ้งเหตุความปลอดภัย

  1. พนักงานเปิดเว็บ → เบราว์เซอร์ส่ง GET request ไปที่เซิร์ฟเวอร์ → เซิร์ฟเวอร์ส่งหน้าฟอร์ม (HTML) กลับมา
  2. พนักงานกรอกฟอร์มแล้วกด "ส่ง" → เบราว์เซอร์ส่ง POST request พร้อมข้อมูลที่กรอก ไปที่เซิร์ฟเวอร์
  3. เซิร์ฟเวอร์ (backend) รับข้อมูล ตรวจสอบความถูกต้อง แล้วบันทึกลง database
  4. เซิร์ฟเวอร์ส่ง response กลับไปว่า "บันทึกสำเร็จ" → เบราว์เซอร์แสดงข้อความแจ้งเตือนให้พนักงานเห็น

สังเกตว่าข้อมูลรายงานอุบัติเหตุ ถูกเก็บอยู่ใน database บนเซิร์ฟเวอร์ ไม่ใช่ในเบราว์เซอร์ของพนักงานคนนั้น — ดังนั้นหัวหน้างานคนอื่นที่เปิดเว็บเดียวกันจากเครื่องอื่น ก็จะเห็นรายงานเดียวกันได้ทันที นี่คือเหตุผลที่เราต้องมีทั้ง 3 ส่วนแยกกัน

ถามครูได้ตลอดบทเรียน

ถ้ามีศัพท์ไหนงงๆ หรืออยากให้ยกตัวอย่างจากงาน ESS จริงมากกว่านี้ (เช่น เคสเงินเดือน) ถามในแชทได้เลย ไม่ต้องรอให้จบบทเรียน — Claude เป็นครูของบทเรียนนี้ ถามได้ตลอด

บทต่อไปจะเรียนอะไร

ตอนนี้เรารู้ภาพรวมแล้วว่ามี 3 ส่วน (frontend / backend / database) คุยกันด้วย HTTP บทเรียนที่ 2 เราจะเริ่ม ลงมือเขียน HTML จริง — สร้างหน้าฟอร์มแจ้งเหตุความปลอดภัยหน้าแรกขึ้นมาด้วยมือตัวเอง (ยังไม่ต้องมี backend) เพื่อให้เห็นว่า frontend เพียวๆ หน้าตาเป็นยังไง ก่อนจะค่อยๆ ต่อกับ backend ในบทหลังๆ
