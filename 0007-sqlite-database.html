บทเรียนที่ 7 · ทำให้ข้อมูลอยู่ถาวร

ฐานข้อมูล SQLite: ข้อมูลไม่หายอีกต่อไป

ใช้เวลาทำประมาณ 25-30 นาที · ต่อยอดจาก server.js ในบทที่ 6

เป้าหมาย · สร้างระบบเงินเดือน/ความปลอดภัยใช้เองที่ ESS

บทที่แล้วข้อมูลเก็บใน array — พอ restart server ข้อมูลหายหมด สำหรับระบบที่ใช้งานจริงในบริษัทแบบนี้ไม่ได้แน่นอน วันนี้จะเปลี่ยนไปเก็บใน SQLite ฐานข้อมูลที่เก็บเป็นไฟล์เดียว ไม่ต้องติดตั้ง server ฐานข้อมูลแยก — เหมาะกับ internal tool ขนาดเล็กแบบระบบแจ้งเหตุนี้พอดี

1. ติดตั้ง better-sqlite3

npm install better-sqlite3

เป็น library ที่นิยมที่สุดตัวหนึ่งสำหรับใช้ SQLite ใน Node.js เขียนง่าย ทำงานแบบ synchronous (ไม่ต้องยุ่งกับ async/await ตอนคุยกับฐานข้อมูล ซึ่งเหมาะกับแอปขนาดเล็กแบบนี้)

2. สร้างตารางเก็บรายงาน

เพิ่มโค้ดนี้ต่อจาก require('express') บนสุดของ server.js:

const Database = require('better-sqlite3');
const db = new Database('reports.db');

db.exec(`
  CREATE TABLE IF NOT EXISTS reports (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    reporterName TEXT,
    incidentDate TEXT,
    location TEXT,
    incidentType TEXT,
    severity TEXT,
    details TEXT,
    createdAt TEXT
  )
`);

CREATE TABLE IF NOT EXISTS แปลว่า "สร้างตารางนี้ถ้ายังไม่มี" — รันซ้ำกี่ครั้งก็ไม่พังตารางเดิม INTEGER PRIMARY KEY AUTOINCREMENT คือให้ SQLite นับเลข id ให้เองอัตโนมัติทีละ 1 ไม่ต้องคำนวณเองแบบตอนใช้ array

3. แก้ route ให้ INSERT ลงฐานข้อมูลจริง

const insertReport = db.prepare(`
  INSERT INTO reports (reporterName, incidentDate, location, incidentType, severity, details, createdAt)
  VALUES (@reporterName, @incidentDate, @location, @incidentType, @severity, @details, @createdAt)
`);

app.post('/api/reports', (req, res) => {
  const createdAt = new Date().toISOString();
  const result = insertReport.run({ ...req.body, createdAt });
  res.json({ success: true, message: 'บันทึกรายงานแล้ว (รายการที่ ' + result.lastInsertRowid + ')' });
});

db.prepare(...) เตรียมคำสั่ง SQL ไว้ล่วงหน้า (เร็วกว่าและปลอดภัยกว่าการต่อ string SQL เอง — ป้องกันการโจมตีแบบ SQL injection ไปในตัว) ส่วน @reporterName คือ placeholder ที่จะถูกแทนที่ด้วยค่าจาก object ที่ส่งเข้าไปตอนเรียก .run()

4. แก้ route ให้ SELECT จากฐานข้อมูลจริง

const getAllReports = db.prepare('SELECT * FROM reports ORDER BY id DESC');

app.get('/api/reports', (req, res) => {
  res.json(getAllReports.all());
});

ORDER BY id DESC คือเรียงจากรายการล่าสุดขึ้นก่อน (DESC ย่อจาก descending)

แผนภาพ 5 — ระบบแจ้งเหตุความปลอดภัยทำงานครบวงจรจริง ข้อมูลอยู่ถาวรใน reports.db

5. ทดสอบความถาวร

  1. รัน node server.js, ส่งฟอร์มสัก 2-3 รายการ
  2. กด Ctrl+C ปิด server ใน terminal
  3. รัน node server.js ใหม่อีกครั้ง
  4. เปิด http://localhost:3000/api/reports — ข้อมูลเดิมยังอยู่ครบ!

ลองเปิดไฟล์ reports.db ดูก็ได้ (เป็นไฟล์ binary เปิดตรงๆ ไม่ได้ แต่มีเครื่องมือฟรีอย่าง DB Browser for SQLite เปิดดูตารางแบบเห็นภาพได้)

ข้อมูลพนักงาน/เงินเดือน ต้องระวังอะไรเพิ่ม

ถ้าจะเอาไปใช้กับข้อมูลเงินเดือนจริง มีเรื่องต้องคิดเพิ่มจากนี้ เช่น การเข้ารหัสไฟล์ฐานข้อมูล การจำกัดสิทธิ์ว่าใครดูอะไรได้บ้าง (authentication/authorization) — ยังไม่ครอบคลุมในคอร์สนี้ แต่ถามได้เลยถ้าอยากรู้ทิศทางคร่าวๆ ก่อนจะเอาไปใช้จริงกับข้อมูลอ่อนไหว
